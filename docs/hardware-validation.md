# Hardware / 机械验证记录

> **2026-10-20：当前 B 线用 Juxi B 线 CAD/STL**，见 [`../hardware/juxi_b_line/`](../hardware/juxi_b_line/)；本清单的纸板/转台/甩棍内容是旧“底部方位+顶部打击”备选方案的验证，不适用于当前 B 线 2R 臂。  
> B 线重点：打印后称重/量尺寸、舵机 1520µs 中位、肩/肘方向、末端垫防滑、整机质量 vs 仿真 97.4 g。

## 0. 实机 B 线验证（2026-10-22，已组装）

装配：SelfRisingRobot 5 个打印件（footP、arm1P、arm2P、armhornP×2）+ 2×PTK7452MG + ESP32-S3 + Juxi IMU。  
固件：`firmware/sr_support_b_ptk`（PlatformIO，COM27），串口命令见其 README。

- [x] IMU：直立 `up=(0.00, 0.03, 1.00)`；侧躺 `up=(1.00, -0.03, -0.03)`，方向跟随正确，静止陀螺≈0。
- [x] 舵机回中：`r` → `servo re-armed at neutral`，`q=0.00 0.00`（1520 µs）。
- [x] 自检：`t` 执行 `+0.5 → -0.5 → 回中`。
- [x] 单关节/任意角：`1/2/3/4/0`、`m q1 q2` 均可执行并保持。
- [x] **手动扶正（侧躺 → 直立）**：依次 `m -0.50 -1.55`、`m +1.55 -1.55`、`m +1.55 +1.55`、`m -1.55 -1.55`、`m -1.55 0.00`、`m +0.50 -1.55`，`up_z` 从 0 到 **0.96**；再 `m 0 0` 收臂到竖直，`up=(0.00, 0.03, 1.00)`，`r` 回中保持。脚本：[`../tools/hw_right.py`](../tools/hw_right.py)。
- [x] **IMU 读取节流（2026-10-22 修复）**：固件原来在主循环里无节流读 IMU，50 Hz 快速日志显示 I2C 读大量失败、原始值长期为 0，Mahony 姿态冻结在最后一次成功值；机器人被推倒后策略仍看到“直立”，出现抖动抽搐。改为固定 **100 Hz** 读取后，快速日志原始值连续变化（0/86 重复）。诊断工具：[`../tools/hw_log.py`](../tools/hw_log.py)（固件命令 `l` 输出 3 s 50 Hz 日志）。
- [x] **舵机方向确认（2026-10-22）**：IMU `+Y` 在 `+X` 左侧（标准机体坐标，无需翻转）；实测 `shoulder +0.5` 大臂向 **−Y**、`elbow +0.5` 小臂向 **+X**，与仿真关节方向一致。对应固件 `SERVO_SHOULDER_SIGN=-1`、`SERVO_ELBOW_SIGN=-1`（默认值已写死；`v`/`b` 仅作现场微调）。
- [x] **v5_pitchneg 专项微调（2026-10-22）**：v5 在 `pitch_neg`（−X 倒）是 0/10 的系统性弱点；专项微调后四方向 10/10，DR 83.3%（right_side 66.7%）。但实机仍出现肘关节 50 Hz 极限环（`q2` 每 20 ms 反向，15 s 内 682 次），降限速只减小幅度、不能起立。**结论：接线/符号正确，剩余差距是舵机死区/回差与臂-地接触，脚本模式暂为可靠路径。**
- [x] **舵机方向校准（2026-10-22）**：实机确认 `shoulder +0.5 → −Y`、`elbow +0.5 → +X`，与仿真一致；默认写成 `SERVO_SHOULDER_SIGN=-1`、`SERVO_ELBOW_SIGN=-1`。`v`/`b`/`i`/`j` 运行时校准命令保留，供后续排查。
- [x] **脚本自动扶正兜底（2026-10-22）**：固件 `a` 模式检测 `up_z<0.5` 持续 0.5 s 后执行实测扶正序列（6 个姿态 ×1.3 s），站起后回中；与 `hw_right.py` 同一序列。
- [x] 实机策略已导出烧录（v5_pitchneg，10→128→128→2）并含站立收臂状态机；当前剩余问题是舵机死区/回差导致的极限环，脚本 `a` 作为可靠兜底。
- [ ] 逐件称重，更新 `tools/build_selfrising_model.py` 的 `MASS_*` 并重训。
- [ ] 舵机堵转/温度/电流实测（PTK7452 无反馈，靠目视/手感/时间限制）。
- [ ] 四个倒地方向各 ≥8/10、连续 100 次。

> 手动扶正只验证了机构/扭矩/接线，不代表策略可用；侧躺之外的姿态需要另找序列。测试中注意舵机堵转 ≤1 s、外壳温度 <60°C。

## 0.3 自扶正执行器实机验证（2026-10-27，参考+反馈执行器）

固件：`firmware/sr_support_b_ptk`（PlatformIO `ptk7452`，COM27，RAM 7.3% / Flash 11.7%）。
算法：`training/b_line/getup_executor.py` 与 C 实现逐参数一致：

- 20 控制拍（0.4 s）/参考路点；每拍输出限速 0.08 rad；最后阶段以 0.033 rad/拍收臂到中立；
- 完成判定：up_z>0.95 且目标归零持续 50 拍；单次参考 14 s 超时；结束后 75 拍冷却；
- 跌倒门：up_z<0.30 且 |ω|<0.9 rad/s 连续 25 拍（0.5 s）才启动（解决“放下立即乱摆、等一会才正常”）；
- 姿态重规划：up_z<0.6 且 |ω|<0.8 持续 15 拍 → 中立回撤（≤120 拍）→ 新姿态参考，最多 5 次；
- 姿态分类用机体 up 向量（无欧拉角万向锁）：|ux|≥|uy| → pitch（ux<0 为 pitch_pos），否则 roll（uy>0 为 roll_pos）。

已部署参考序列（rad，肩/肘）：

| 姿态 | 序列 |
|---|---|
| roll_pos | `[2.0,-0.8] → [0,-0.8] → [0,0]` |
| roll_neg | `[2.0,-0.8]×4（保持）→ [0,-0.8] → [0,0]` |
| pitch_pos | `[-1.07,1.55] → [0,1.55] → [0,0]` |
| pitch_neg | `[-1.07,-1.55] → [0,-1.55] → [0,0]` |

- [x] **pitch_neg（up≈(+1,0,0)）**：实机干净扶正约 3 s（17:04:46 `done`，无重规划）。
- [x] **pitch_pos（up≈(−1,0,0)）**：多次由重规划接手执行并站稳（16:09:37、17:09:53 等）；仿真 22 项中 pitch 全过。
- [x] **roll_pos（up≈(0,+1,0)）**：直接杠杆扶正，实机 15:38:49 约 3 s `done`。
- [x] **roll_neg（up≈(0,−1,0)，肩摆动方向）**：实机 4/4 成功（17:09:47 / 17:10:03 / 17:10:24 /
  17:10:37，5–14 s）。机制：手臂甩到 +2.0 保持 → 手臂质量把身体绕长轴滚过顶部 → 姿态重规划在
  身体停稳于俯仰轴后接俯仰序列蹬地扶正。单次可能切换 0–3 次，属该方向的正常机制。
- [x] 全部测试无舵机越界（监控 `tools/hw_monitor.py`，日志 `logs/hw_monitor.log`）。
- [x] 串口执行轨迹 5 Hz：`executor pose=... ph=... tgt=... up=... q=... sw=...`，
  以及 `executor re-plan A -> B up=...` 事件。

**已验证不可行的方案（勿重复尝试）**：

- [x] 小臂拖地转轴（仿真 roll_neg 的实际机制）：实机身体 up 全程只晃 ±0.1，地面摩擦传力不足。
- [x] 快速回扫直接接俯仰（+2.0 → −1.07）：回扫把身体滚回原侧，随后蹬地无效。
- [x] 慢收臂后连续蹬地（方案 1 连续化，18:21:51 完整轨迹）：同样滚回原侧后蹬地失效。
- [x] 几何限制：肩反向行程仅 −1.07 rad，无法在身体另一侧撑地；roll_neg 不存在“直接一步撬起”的解，
  滚过顶部换边是唯一途径。
- [x] 仿真 1× 模型不能复现 roll_neg 实机动作（模型手臂质量/摩擦与实机不同；实机手臂在仿真中约等效
  2× 质量）。当前 roll_neg 序列为实机专用，仿真回归中该方向不通过属已知差异。

**待办**：

- [ ] roll_neg 连续多测（≥8/10 次）统计成功率与平均用时。
- [ ] 小臂接触面贴高摩擦材料（橡胶/硅胶条）验证拖地转轴是否成立；若成立可改用更直接的参考序列。
- [ ] （可选）肩舵机换齿改对称约 ±90°：两侧都有直接撑地杠杆，但所有参考序列需重调。
- [ ] 逐件称重更新模型手臂质量（≈2×），使仿真与实机一致后再重搜参考序列。

首版不要直接打印外壳。先纸板/木条验证力臂和接触点，避免“纸上能站、实物站不起来”。

## 1. 纸板侧视图

- [ ] 画出机身轮廓、翻倒边（支点）、重心投影、棍端/臂端撑地点。
- [ ] 确认撑地点落在**支点外侧**（支撑多边形之外）。
- [ ] 确认地面反力对支点产生的力矩**与倾倒方向相反**。
- [ ] 如果不满足，先改舵机位置/棍长/臂长/角度，不要加大舵机扭矩。

## 2. 单舵机（简化验证）

- [ ] 用纸板/木条/亚克力做摆臂，热熔胶或扎带固定 SG90。
- [ ] 手动把机身推倒，观察臂端是否撑地、机身是否被顶回。
- [ ] 先不装壳、不埋槽，方便反复改位置。
- [ ] 记录失败原因：臂太短、接触点在支点内、打滑、干涉、扭矩不够。

## 3. 两舵机（主方案）

### 3.1 底部转台

- [ ] 底部舵机输出轴竖直，转台重心落在轴线上。
- [ ] 加轴承/铜套，底部舵机只承受旋转扭矩，不承受顶部舵机+棍子的侧向力。
- [ ] 转台画 0°/90°/180° 基准线；记录底部舵机脉宽与角度的对应关系。
- [ ] 手转机身到不同方位，确认 `azimuth` 映射到底部角度方向正确；不反、不偏 90°。
- [ ] 用手轻推转台，检查是否有明显间隙/back-drive；必要时加摩擦片/机械锁。

### 3.2 顶部甩棍

- [ ] 棍长 80–150 mm 起步；轻、硬、直；末端橡胶/硅胶头。
- [ ] 顶部舵机中位收棍，A/B 两侧甩出；先空打（不接触地面），确认方向/速度/不干涉。
- [ ] 棍子扫掠不要打到机身、线缆、桌面边缘。
- [ ] 顶部舵机先 MG90S；加 servo saver/弹性棍头/机械限位。
- [ ] 慢速倒地轻打：棍端接触点在支点外侧，能阻止继续倒或把机身顶回。
- [ ] 记录不同方位的成功率；失败方向检查瞄准映射/棍长/转台反力。

### 3.3 布线/电源

- [ ] 顶部舵机线经过转台，留足够余量；180° 方案不要绷紧。
- [ ] 两个舵机 5V 线从电源端子分开引出；2200 µF 就近；2 A 保险丝。
- [ ] 两个舵机同时动作，测 5V 跌落和 ESP32 是否复位。

## 5. 通过标准

- [ ] 单舵机：目标方向推倒后，200 ms 内判定、300 ms 内展臂，8/10 站起。
- [ ] 两舵机：任意方向推倒，底部提前瞄准、顶部打击，≥6/10 能阻止继续倒或扶正。
- [ ] 连续 50 次不扫齿、不复位、不烫手；转台无明显间隙。
- [ ] 失败方向有明确提示/锁定，而不是无限堵转。
