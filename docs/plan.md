# 项目计划（2026-10-26）

> 注（2026-11 瘦身）：文中出现的 `hardware/juxi_b_line/`、`bom/`、`firmware/sr_support_2dof/`、旧仿真模型与变体 XML 已从仓库移除，相关描述仅作历史记录；当前模型见 [`hardware/v1/`](../hardware/v1/)。

本文件把当前阶段的现状、约定、计划和待拍板事项固定下来，避免再出现“仿真自然扶正、实机只有固定动作”这类理解偏差。

## 0. 一句话结论

实机“只有固定动作”的主因不是策略不会看 IMU，而是**实机几何和已烧录策略的训练几何不一致**：样机是 +6 cm 垫高、26 cm 臂高；已烧录的 v7 策略是在原版几何（无垫高、6 cm 臂）上训练的。更关键的是，仿真已经证明 +6 cm 垫高的几何会**楔死在伸出的手臂上**——任何策略在这个几何上都会呈现“伸手臂 → 卡住”的相似动作，看起来与倒地方向无关。

## 1. 现状

已确认的事实：

- 实机尺寸（2026-10-23 实测）：底盘 8.5×8.5 cm；底盘自身垫高 6 cm；底盘顶面到立直最高点 26 cm（手臂加长实际为 9.2 cm）。
- 垫高与站直能力的关系：手臂伸到极限时，身体离竖直的差值约为 **1 cm 垫高 ≈ 2.8°**（0 cm→6.6°，3 cm→15.4°，6 cm→23.4°）。23.4° 落在“手臂顶地楔死”的区间。
- 楔死是运动学的：收臂、卸力、肘关节、摆动、摩擦、随机轨迹搜索都无法挣脱；增加训练或换策略本身解决不了。
- 解法（仿真已验证）：肩关节行程从 ±88.8°（±1.55 rad）扩到 **±115°（±2.0 rad）**，再由“压臂→保持→慢收”流程完成立直。标称 14/14，域随机化 10/12。
- 固件当前仍是 v7 策略（5 维接口），未包含压臂流程；关节范围仍是 ±1.55 rad。

## 2. 约定（描述动作时统一使用）

坐标系（机身系）：**x 前、y 左、z 上**。`up_b` = 世界竖直方向在机身系中的表示；直立时 `up_b=(0,0,1)`，`up_z=1`。

| 项 | 约定 | 备注 |
|---|---|---|
| 肩关节 `q1`（GPIO4） | 绕机身 x 轴；`q1=0` 手臂竖直向上；正方向使手臂向 **−Y** 侧摆 | 限位 ±1.55 rad（方案改后正向到 2.0） |
| 肘关节 `q2`（GPIO5） | 绕机身 y 轴；正方向使小臂向 **+X** 侧摆 | 限位 ±1.55 rad |
| IMU 轴 | 芯片 +Y 在 +X 的**左侧**（与机身系一致） | 见 `firmware/.../config.h` 注释 |
| 倒地方向命名 | `roll_pos/roll_neg`=绕 x 轴；`pitch_pos/pitch_neg`=绕 y 轴 | 训练/评估脚本一致 |
| “立直/站立” | `up_z>0.9` 且手臂 `|q|<0.35`（收臂到位） | 只有身体立起不算成功 |

## 3. 计划

### Phase 1 机械方案拍板（已决定 2026-10-26）
- **决定：保留 180° PTK7452MG 舵机**，肩舵盘错齿 2 齿（25T，~28.8°），肩关节行程变为 [-1.07, +2.07] rad（总行程 179.9°，合法）。错齿方向：手臂竖直位朝短行程（负）侧偏 29°。
- 备选（未采用）：270° 舵机（对称 ±2.0 rad，仿真模型 `robot_selfrising_r60l6_h26_r20.xml`，标注 270° 专用）。
- 交付：机械错齿 + q=0 脉宽零点重标定。

### Phase 2 仿真定稿（基本完成，待实机校准收敛）
- 几何：`r60l6h26ri_sr5`（`robot_selfrising_r60l6_h26_ri.xml`；肩 [-1.07,+2.07]，肘 ±1.55）。
- 策略：`ppo_r60l6_ri3/final.zip`（自己会压臂过水平线）；控制器 `PushStand`（先压回 ±2.0 → 保持 0.6 s → 慢收，下垂回压）。
- 结果：标称四方向 + 随机 **10–14/14** 立直（up=1.0，q=0）；域随机化 ~4–6/10，收臂阶段对舵机特性敏感，需实机标定 `pause/retract_rate`。
- 状态：定稿，等实机数据回调参数。

### Phase 2b 底盘 39 mm 版本（2026-10-26）
- 几何：`b39h26ri_sr5`（`robot_selfrising_b39_h26_ri.xml`；底盘 8.5×8.5×39 mm，臂 26 cm，肩 [-0.8,+2.07]，肘 ±0.8）。
- 策略：`ppo_b39_qm08/final.zip` + `PushStand`（含 left_pump 肘部翻滚救援）。
- 结果：标称 **14/14**（四方向 + 10 随机姿态全部立直 up=1.0、q=0）；域随机化 4/10（左侧救援对舵机特性敏感，需实机标定）。
- left_side 解决方式：短侧撑死时把肘压到限位并小幅摆动（pump），身体翻到另一侧后由策略接管。
- 状态：标称定稿；DR 参数待实机回调。

### Phase 3 固件实现（1–2 天）
- 关节范围/脉宽映射更新（270° 舵机：脉宽范围不变，角度常量 1.55→2.0）。
- 站立状态机加“压臂 → 保持 0.6 s → 慢收（≤0.005 rad/步，倾斜暂停）→ 竖直位”。
- 导出策略（`tools/export_policy.py`，5 维）并烧录。
- 交付：台架可复现的完整流程。

### Phase 4 仿真到实机校准（半天，逐项打勾）
1. 静态四点倾斜：把机器人分别朝 ±X、±Y 倾斜 30–45°，用 `l` 快日志记录 `up` 向量，与约定表核对符号。
2. 单关节核对：`1/2` 手动命令 ±0.5、±1.0 rad，量实际摆角与方向（肩→−Y，肘→+X）。
3. 观测回放：抓一段实机 50 Hz 日志的 `up/q`，在 PC 上喂给策略，对比“策略输出动作”与实机实际动作——分离“观测错”还是“执行错”。
4. 时序：IMU 100 Hz、控制 50 Hz、指令延迟约 1 步；与仿真参数对齐。

### Phase 5 实机分级测试
- 架空（负载测试）→ 单侧倒地 → 四方向 → 反复推倒 10 次。
- 每级记录：up 轨迹、q 轨迹、是否完成、耗时；不达标不进入下一级。

### Phase 6 收尾
- 归档实验几何（`training/b_line/assets/` 下 r60l6 系列、split 系列保留但标注）。
- 文档更新：训练 README、固件 README、hardware-validation 增补“垫高-倾角”结论。

## 5. “实机上只有固定动作”的排查顺序（Phase 4 之前先排除）

1. 确认当前跑的是策略 `g` 而不是固定脚本 `a`（串口会打印状态）。
2. 策略启动门控：`up_z<0.5` 持续 0.2 s 才 arm；侧倒时若 `up_z` 不足够低，策略不会接管。
3. 几何不匹配（主因，见第 1 节）：在 +6 cm 垫高几何上，原策略必然楔死。
4. 观测/方向约定（用 Phase 4 的回放法确认）。
